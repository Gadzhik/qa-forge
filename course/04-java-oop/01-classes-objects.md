## Зачем нужны объекты

До сих пор мы хранили данные в отдельных переменных: `String name`, `double price`, `int stock`. Но в QA Burger 20 товаров, у каждого имя, цена, категория, остаток... Хранить это в десятках разрозненных переменных невозможно.

**Объектно-ориентированное программирование (ООП)** предлагает объединять **данные** и **действия над ними** в одно целое — **объект**. Товар «Кола» — объект: у него есть данные (имя, цена) и поведение (посчитать стоимость N штук, сказать, дорогой ли он).

- **Класс** — чертёж, шаблон: «у каждого товара есть имя и цена, товар умеет считать стоимость».
- **Объект** (экземпляр класса) — конкретная вещь по чертежу: «Кола за 99 ₽», «Бургер за 289.90 ₽».

Один класс — сколько угодно объектов.

## Объявление класса

```java
public class Product {
    // 1. Поля — данные объекта
    private String name;
    private double price;

    // 2. Конструктор — как создать объект
    public Product(String name, double price) {
        this.name = name;
        this.price = price;
    }

    // 3. Методы — поведение
    public String getName() {
        return name;
    }

    public double costOf(int quantity) {
        return price * quantity;
    }
}
```

### Поля

```java
private String name;
private double price;
```

**Поля** (fields) — переменные, объявленные прямо в классе, вне методов. У **каждого объекта свои** значения полей: у колы `name = "Кола"`, у бургера — `"Бургер"`. `private` — поле доступно только внутри класса (почему — в уроке 4.2).

Если поле не заполнить, у него будет значение по умолчанию: `0`, `false` или `null`.

### Конструктор

```java
public Product(String name, double price) {
    this.name = name;
    this.price = price;
}
```

**Конструктор** — особый метод, который вызывается при создании объекта и заполняет его поля.
- Его имя **совпадает с именем класса**;
- у него **нет типа возвращаемого значения** (даже `void`);
- параметры — то, что нужно передать при создании.

**`this`** — ссылка на «текущий объект», тот, который сейчас создаётся. Зачем он здесь: параметр называется `name` и поле называется `name`. Внутри конструктора просто `name` — это параметр (ближайшая переменная «затеняет» поле). `this.name` — однозначно поле объекта. Строка `this.name = name;` читается: «в поле name этого объекта положить значение параметра name».

> ⚠️ Классическая ошибка: `name = name;` — параметр присвоили сам себе, поле осталось `null`. IDEA подсветит такую строку предупреждением.

### Методы объекта

```java
public double costOf(int quantity) {
    return price * quantity;
}
```

Заметьте: **нет слова `static`**. Такой метод принадлежит объекту и работает с **его** полями: `price` здесь — цена именно того товара, у которого вызвали метод.

## Создание и использование объектов

```java
Product cola = new Product("Кола", 99.0);
Product burger = new Product("Классический бургер", 289.9);

System.out.println(cola.getName());        // Кола
System.out.println(burger.costOf(2));      // 579.8
```

- `Product cola` — переменная типа `Product` (ссылочный тип, хранит ссылку на объект);
- `new Product("Кола", 99.0)` — **`new` создаёт объект** в памяти и вызывает конструктор с этими аргументами;
- `cola.getName()` — **точка** означает «у объекта cola вызвать метод getName».

Два объекта — два независимых набора полей:

```text
 cola ──▶ ┌───────────────────┐      burger ──▶ ┌──────────────────────────────┐
          │ name  = "Кола"    │                 │ name  = "Классический бургер" │
          │ price = 99.0      │                 │ price = 289.9                 │
          └───────────────────┘                 └──────────────────────────────┘
```

## Геттеры

```java
public String getName() {
    return name;
}
```

Поле `private`, поэтому снаружи прочитать его можно только через метод. Такие методы называют **геттерами** (get — получить). Соглашение об именах: `getИмяПоля()`, для `boolean` — `isИмяПоля()`. Его используют многие библиотеки (например, Jackson в модуле 6 превращает объект в JSON именно через геттеры), так что соблюдать его важно.

IDEA генерирует геттеры сама: **Alt+Insert** (⌘N) → *Getter* → выбрать поля.

## Конструктор по умолчанию

Если в классе нет ни одного конструктора, Java добавляет пустой конструктор без параметров: `new Product()`. Но как только вы написали свой конструктор с параметрами, пустой **исчезает**: `new Product()` станет ошибкой компиляции. Нужны оба — пишите оба (урок 4.3).

## Где объекты в автотестах

Повсюду:
- `RequestSpecification` в REST Assured — объект с настройками запроса;
- **Page Object** (модуль 10) — объект, описывающий страницу: `loginPage.login("user", "user123")`;
- **модели данных** — объекты, в которые превращается JSON из ответа API: `ProductDto`, `OrderDto`;
- сам тест-класс — тоже класс; JUnit создаёт его объект перед каждым тестом.

## Несколько конструкторов

Объект можно создавать по-разному: заказ с промокодом и без. Для этого пишут **несколько конструкторов** (это перегрузка, как у методов):

```java
public class Order {
    private final String promoCode;

    public Order(String promoCode) {
        this.promoCode = promoCode;
    }

    public Order() {
        this(null);           // вызвать первый конструктор с promoCode = null
    }
}
```

**`this(...)`** — вызов **другого конструктора этого же класса**. Так логику создания пишут в одном месте, а остальные конструкторы к нему обращаются. Правило: `this(...)` должен быть **первой** строкой конструктора.

Не путайте:
- `this.поле` — обращение к полю текущего объекта;
- `this(...)` — вызов другого конструктора;
- `this` — ссылка на текущий объект целиком (например, `return this;`).

## static — «общее для всех объектов»

Обычные поля принадлежат **объекту**: у каждого заказа свой номер. Иногда нужны данные, общие для **всего класса**: например, счётчик созданных заказов.

```java
public class Order {
    private static int createdCount = 0;   // одно на весь класс
    private final int number;              // своё у каждого объекта

    public Order(String promoCode) {
        createdCount++;                    // увеличили общий счётчик
        this.number = createdCount;        // запомнили номер этого заказа
        this.promoCode = promoCode;
    }

    public static int getCreatedCount() {
        return createdCount;
    }
}
```

```java
new Order("SALE10");   // number = 1
new Order();           // number = 2
System.out.println(Order.getCreatedCount());   // 2
```

```text
                  класс Order
           ┌──────────────────────┐
           │ createdCount = 2     │   ← static: одна копия
           └──────────────────────┘
   объект 1                     объект 2
 ┌───────────────┐          ┌───────────────┐
 │ number = 1    │          │ number = 2    │  ← у каждого своё
 │ promo=SALE10  │          │ promo = null  │
 └───────────────┘          └───────────────┘
```

**Статические методы** вызываются через имя класса: `Order.getCreatedCount()`, `Math.max(1, 2)`, `Integer.parseInt("5")`. Им не нужен объект — поэтому внутри статического метода **нет `this`** и нельзя обращаться к обычным полям (каким объектом? их нет).

> ⚠️ `Non-static field 'number' cannot be referenced from a static context` — классическая ошибка: из статического метода (например, `main`) обратились к обычному полю. Решение: создать объект (`new ...`) или сделать поле/метод статическим, если оно действительно общее.

## Когда static уместен

- **Константы**: `public static final int MAX_QUANTITY = 99;`
- **Утилитные методы**, которым не нужно состояние: `Math.abs`, `Assertions.assertThat`, наши методы из модуля 3.
- **Фабричные методы**: `Money.of(289, 90)` — красивый способ создать объект (урок 4.4).

## Когда static вреден — важно для автотестов

Статическое изменяемое поле — **общее состояние** для всего, что работает в программе. Тесты, запущенные подряд или **параллельно**, начинают влиять друг на друга:

```java
public class TestData {
    public static String token;   // ❌ тест А записал свой токен, тест Б его перезаписал
}
```

В задании ниже вы это увидите: проверки `OrderCheck` вынуждены сбрасывать счётчик перед каждым тестом (`Order.resetCounter()`), иначе номера заказов зависели бы от порядка запуска тестов. Мы вернёмся к этому в модуле 14 (параллельный запуск).

## Блок инициализации и порядок создания (для собеседований)

```java
public class Demo {
    static { System.out.println("1. статический блок — один раз при загрузке класса"); }
    { System.out.println("2. блок инициализации — перед каждым конструктором"); }
    public Demo() { System.out.println("3. конструктор"); }
}
```

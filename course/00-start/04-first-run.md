## Запуск курса

Скорее всего, вы уже запустили курс, раз читаете этот урок. Но разберём, что именно происходит, — это хороший пример того, как запускаются Java-приложения.

```tabs
Windows: |
  Двойной клик по `start.cmd` в Проводнике. Или в PowerShell, находясь в папке курса:

  ~~~powershell
  .\start.cmd
  ~~~

  Откроется окно консоли, в нём запустятся QA Burger и портал. Через ~15 секунд браузер сам откроет http://localhost:8080.
  Пока учитесь, окно не закрывайте — можно свернуть.

  **Остановить курс** — любой из способов:
  - закрыть это окно;
  - нажать в нём **Ctrl+C** (на вопрос «Завершить выполнение пакетного файла?» ответить `Y`);
  - двойной клик по `stop.cmd` в папке курса.
macOS / Linux: |
  В терминале перейдите в папку курса и выполните:

  ~~~bash
  ./start.sh
  ~~~

  Браузер откроется сам. Пока учитесь, терминал не закрывайте — можно свернуть.

  **Остановить курс** — любой из способов:
  - нажать **Ctrl+C** в этом терминале;
  - закрыть окно терминала;
  - в другом терминале в папке курса выполнить `./stop.sh`.
```

**Первый запуск занимает 3–10 минут**: Maven скачивает из интернета все библиотеки (Spring, JUnit, Selenium и т.д.) — около 300 МБ — и складывает их в папку `~/.m2/repository`. Следующие запуски — секунд 20.

### Что внутри start.sh

Откройте `start.sh` в любом редакторе. Главные строки:

```bash
cd "$(dirname "$0")"
```

- `$0` — путь к самому скрипту;
- `dirname` — отрезает имя файла и оставляет папку;
- `cd` — переходим в эту папку.

**Зачем:** чтобы скрипт работал, откуда бы вы его ни запустили. Все пути дальше (`shop-app/target/...`) отсчитываются от папки курса.

```bash
JAVA_MAJOR=$(java -version 2>&1 | head -n1 | sed -E 's/.*version "([0-9]+).*/\1/')
```

Узнаём «главный» номер версии Java:
- `java -version` печатает версию, причём в **поток ошибок** (так исторически сложилось);
- `2>&1` — перенаправляем поток ошибок (2) туда же, куда обычный вывод (1), иначе `|` его не увидит;
- `head -n1` — берём первую строку;
- `sed -E 's/.../\1/'` — регулярным выражением вырезаем число после `version "`.

```bash
./mvnw -q install -Dmaven.test.skip=true -pl shop-app,portal,exercises/test-support -am
```

Сборка проекта (подробно — в модуле 6):
- `./mvnw` — Maven Wrapper: сам скачает Maven нужной версии, ставить его не нужно;
- `-q` (*quiet*) — печатать только ошибки;
- `install` — собрать и положить результат в локальное хранилище `~/.m2`;
- `-Dmaven.test.skip=true` — не компилировать и не запускать тесты (их запускают проверки заданий);
- `-pl shop-app,portal,exercises/test-support` (*projects list*) — собрать только эти модули;
- `-am` (*also make*) — и всё, от чего они зависят.

```bash
java -jar "$SHOP_JAR" > logs/shop-app.out 2>&1 &
```

Запуск QA Burger:
- `java -jar файл.jar` — запустить Java-приложение, упакованное в **jar** (Java ARchive — архив с байт-кодом и библиотеками);
- `> logs/shop-app.out 2>&1` — весь вывод в файл, чтобы не мешал;
- `&` в конце — запустить **в фоне** и не ждать завершения.

```bash
trap cleanup EXIT INT TERM HUP
```

`trap` — «ловушка»: при каком событии вызвать функцию `cleanup`, которая останавливает и портал, и QA Burger:
- `EXIT` — скрипт закончился сам;
- `INT` (*interrupt*) — вы нажали Ctrl+C;
- `TERM` (*terminate*) — процесс попросили завершиться командой `kill` (так делает `stop.sh`);
- `HUP` (*hang up*, «повесили трубку») — закрыли окно терминала.

Без ловушки приложения остались бы висеть в фоне и занимать порты 8080 и 8081: при следующем запуске курс бы не стартовал.

```bash
echo "$SHOP_PID" > logs/shop-app.pid
```

- `$!` сразу после запуска в фоне — **PID** (Process ID, номер процесса), его скрипт сохранил в переменную `SHOP_PID`;
- `echo ... > файл` — записать номер в файл `logs/shop-app.pid`.

**Зачем:** `stop.sh` читает этот файл и знает, какой процесс останавливать, даже если окно с `start.sh` уже потерялось.

> 💡 **Ваш прогресс не пропадёт.** Отметки уроков, результаты квизов, заданий и тренажёров портал записывает в файл `~/.qa-course/progress.json` (Windows: `C:\Users\Имя\.qa-course\progress.json`) **сразу после каждого действия**. Остановили курс, перезагрузили компьютер, обновили курс — после запуска всё на месте. Рядом лежит резервная копия `progress.json.bak`.
>
> А вот данные **QA Burger** (заказы, новые пользователи, корзины) хранятся в памяти и при перезапуске сбрасываются к исходным. Это сделано специально: у каждого запуска чистый магазин, и тесты не мешают друг другу.

> 💡 **Порт** — это «номер двери» программы на компьютере. Портал слушает дверь 8080, QA Burger — 8081. Адрес `http://localhost:8081` означает: «на этом же компьютере (`localhost`), дверь 8081». Если порт занят другой программой, приложение не запустится с ошибкой `Port 8081 was already in use`.

## Знакомство с QA Burger

Откройте http://localhost:8081. Это интернет-магазин бургеров. Пройдитесь по нему как обычный покупатель:

1. **Каталог** — поиск, фильтр по категориям, сортировка.
2. **Войти** — тестовые пользователи: `user` / `user123` и `admin` / `admin123`.
3. Положите что-нибудь **в корзину**, перейдите в корзину, введите промокод `SALE10` и **оформите заказ**.
4. На странице заказа нажмите **Оплатить** и понаблюдайте за статусом: `PAID → COOKING → READY`. Статус меняется сам — это работает «кухня» в фоне. Запомните это: в модуле 13 мы будем тестировать такую асинхронность.
5. Внизу страницы есть ссылки:
   - **Swagger** — документация API (модуль 8);
   - **GraphiQL** — консоль GraphQL (модуль 8);
   - **H2** — консоль базы данных (модуль 11);
   - **дизайн v1/v2** — переключение вёрстки (модуль 10, устойчивые локаторы).
6. **Песочница** — страницы с алертами, фреймами, drag&drop и т.д. для UI-тестов.
7. **Тренажёр** — панель, где можно включить любой из 30 багов.

> 🧪 **Попробуй сам.** Откройте «Тренажёр», включите `BUG-302` и сохраните. Добавьте в корзину 2 одинаковых бургера, потом ещё 1. Сколько получилось? Выключите баг и повторите. Именно так выглядит ручное тестирование: есть ожидание («должно стать 3»), есть факт.

## Открываем проект в IntelliJ IDEA

1. Запустите IDEA → **Open** (Открыть).
2. Выберите **папку курса** (ту, где лежит `pom.xml`) → **OK**.
3. IDEA спросит *Trust project?* → **Trust Project** (доверять проекту). Это защита от запуска чужого кода; наш проект безопасен.
4. Справа внизу появится полоса загрузки: IDEA читает `pom.xml`, понимает структуру проекта и индексирует файлы. Дождитесь окончания (1–5 минут).

### Выбираем JDK для проекта

**File → Project Structure** (Ctrl+Alt+Shift+S, на macOS ⌘;) → **Project**:
- **SDK** — выберите установленный JDK 21 (если списка нет — *Add SDK → JDK* и укажите папку из урока 0.2). Можно также выбрать *Download JDK* прямо здесь;
- **Language level** — *SDK default*.

**SDK** (Software Development Kit) — в терминах IDEA это и есть JDK, которым компилируется проект.

### Основные части окна IDEA

| Часть | Где | Что там |
|---|---|---|
| **Project** | слева (Alt+1 / ⌘1) | Дерево файлов проекта |
| **Редактор** | в центре | Открытые файлы во вкладках |
| **Maven** | справа | Модули и команды Maven |
| **Run / Terminal** | снизу (Alt+F12 / ⌥F12 — терминал) | Вывод программ и встроенный терминал |

> 💡 Встроенный терминал IDEA сразу открывается в папке проекта — удобно запускать `./mvnw` без `cd`.

## Первое задание

```task
id: m00-hello
title: Привет, QA!
module: exercises/m00-hello
test: HelloCheck
file: exercises/m00-hello/src/main/java/ru/qacourse/m00/Hello.java
solution: solutions/exercises/m00-hello/src/main/java/ru/qacourse/m00/Hello.java
text: |
  1. В IDEA откройте файл `exercises/m00-hello/src/main/java/ru/qacourse/m00/Hello.java`
     (удобно через **Shift Shift** → начните печатать `Hello`).
  2. Найдите строку с `TODO` и замените `"Hello"` на `"Привет, QA!"`.
  3. Нажмите зелёный ▶ слева от `main` → **Run 'Hello.main()'** и посмотрите вывод внизу.
  4. Сохраните файл (IDEA сохраняет автоматически, но Ctrl+S не повредит) и нажмите **▶ Проверить** здесь.
hint: |
  Текст должен совпасть **символ в символ**: `Привет, QA!` — с большой буквы, запятая, пробел, латинские QA, восклицательный знак.
  Кавычки `"` оставьте — они показывают Java, где начинается и заканчивается текст.
```

Что происходит при нажатии «Проверить»: портал выполняет в папке курса команду

```bash
./mvnw -B -f exercises/m00-hello/pom.xml test -Dtest=HelloCheck
```

- `-B` (*batch*) — режим без цветного «украшательства», удобный для автоматического разбора;
- `-f exercises/m00-hello/pom.xml` — какой модуль собирать;
- `test` — фаза «скомпилировать и запустить тесты»;
- `-Dtest=HelloCheck` — запустить только тест-класс `HelloCheck`.

Тест-класс `HelloCheck` лежит в `exercises/m00-hello/src/test/java/...`. Загляните в него — там всего одна проверка: `assertThat(Hello.greeting()).isEqualTo("Привет, QA!")`. Через пару модулей вы сами будете писать такие проверки.

> 💡 Ту же команду можно выполнить самому во встроенном терминале IDEA и увидеть «сырой» вывод Maven. На Windows вместо `./mvnw` пишите `.\mvnw.cmd`.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `Курс уже запущен` или `Port 8080 was already in use` | Курс уже работает — откройте http://localhost:8080. Чтобы перезапустить, выполните `./stop.sh` (Windows: `stop.cmd`) и запустите снова. Если не помогло — порт занят другой программой: закройте её или перезагрузите компьютер |
| Сборка долго «висит» | В первый раз это нормально — качаются библиотеки. Проверьте интернет |
| `Could not resolve dependencies` | Нет интернета или прокси блокирует Maven Central. Попробуйте другую сеть |
| В IDEA всё красное | Подождите окончания индексации; затем справа панель **Maven** → кнопка 🔄 *Reload All Maven Projects* |
| Проверка пишет «Код не компилируется» | Прочитайте сообщение: номер строки и описание ошибки. Чаще всего — пропущена кавычка или точка с запятой |

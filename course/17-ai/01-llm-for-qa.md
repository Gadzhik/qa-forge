## Что такое LLM — коротко

**LLM** (Large Language Model, большая языковая модель) — программа, обученная на огромном объёме текста и кода, которая по запросу (**промпту**) продолжает текст наиболее правдоподобным образом. Примеры: Claude, ChatGPT, Gemini, GigaChat, YandexGPT, открытые модели (Llama, Qwen).

Важное следствие устройства: модель выдаёт **правдоподобное**, а не обязательно **правильное**. Она может уверенно придумать несуществующий метод библиотеки, неверный код ответа или выдуманное требование. Это называют **галлюцинациями**. Поэтому главное правило:

> 💡 **Ответ нейросети — черновик, а не истина.** Код — запустить, факты — проверить, требования — сверить с первоисточником. Ответственность за результат всегда на вас.

## Где LLM реально экономит время

| Задача | Как помогает | Что проверить за ней |
|---|---|---|
| **Тест-дизайн** | По требованию предложит чек-лист: классы эквивалентности, границы, негативные сценарии | Полноту и соответствие требованиям; модель может пропустить специфичное для вашего продукта |
| **Тест-кейсы** | Оформит идеи в шаги и ожидания | Конкретику значений, реальные названия кнопок |
| **Код автотестов** | Шаблон теста, модель (POJO) по JSON, JSON-схема, Page Object по HTML | Компилируется ли, проходит ли, **ловит ли баг** (урок 7.1!) |
| **Разбор падения** | Объяснит стектрейс, предложит гипотезы | Гипотезы — проверять логами и воспроизведением |
| **SQL и регулярные выражения** | Быстро напишет запрос / regex | Выполнить на реальных данных, проверить края |
| **Тестовые данные** | Сгенерирует разнообразные строки, адреса, «злые» значения | Валидность под ваши правила |
| **Баг-репорт** | Поможет сформулировать понятно | Факты — только ваши |
| **Обучение** | Объяснит незнакомую тему, разберёт код | Сверить с документацией |

## Хороший промпт

Плохо: «напиши тесты для корзины».

Хорошо — дать **роль, контекст, требования, формат и ограничения**:

```text
Ты — QA-автоматизатор. Проект: Java 21, JUnit 5, REST Assured 5, AssertJ.
API корзины: POST /api/cart/items {"productId": long, "quantity": int}, требуется Bearer-токен.
Требования:
- quantity от 1 до 99, иначе 400 с полем code = BAD_QUANTITY;
- повторное добавление того же товара суммирует количество;
- нельзя положить больше остатка (stock) — 400 OUT_OF_STOCK.
Задача: составь чек-лист проверок (позитивные, негативные, граничные значения) таблицей:
№ | сценарий | данные | ожидаемый результат. Не придумывай требования, которых нет в списке —
если чего-то не хватает, перечисли вопросы к аналитику отдельно.
```

Приёмы:
- **Контекст**: стек, версии библиотек, фрагмент кода проекта, формат ответа API — без этого модель гадает.
- **Формат ответа**: таблица, только код, JSON.
- **Запрет выдумывать**: «если не знаешь — так и скажи», «вопросы — отдельным списком».
- **Пошагово**: сначала чек-лист → вы правите → потом код по выбранным пунктам.
- **Примеры** (few-shot): покажите один свой тест — модель повторит стиль.
- **Итерации**: «тест не компилируется, ошибка такая-то» — модель исправит.

## AI-ассистенты в IDE

- **Автодополнение** (JetBrains AI Assistant, GitHub Copilot, Codeium и др.) — дописывает строку/метод по контексту файла.
- **Чат и агенты в IDE / терминале** (Claude Code, Cursor, Kiro, Copilot Chat) — видят проект, могут менять несколько файлов, запускать тесты. Мощно, но требует внимательного **ревью** каждого изменения: агент может «починить» тест, ослабив проверку, вместо того чтобы найти баг.

> ⚠️ Классическая ловушка: попросить ИИ «сделай, чтобы тест прошёл». Он может удалить проверку или поменять ожидание на фактическое (ошибочное) значение. Тест позеленеет, баг останется. Всегда смотрите, **что** изменилось, и задавайте вопрос иначе: «тест падает с такой ошибкой — это баг продукта или ошибка теста? Обоснуй».

## Безопасность и конфиденциальность

- **Не отправляйте** в публичные нейросети: пароли, токены, ключи, персональные данные клиентов, код и документы под NDA. Узнайте правила компании — во многих есть разрешённые корпоративные инструменты.
- Логи и ответы API перед отправкой **обезличьте** (замените email, телефоны, токены).
- Сгенерированный код может содержать уязвимости (склейку SQL, отключённую проверку HTTPS) — ревью обязательно.

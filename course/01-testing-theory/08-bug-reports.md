Нашли дефект — его нужно **описать так, чтобы разработчик мог его воспроизвести и исправить, не задавая вопросов**. Это и есть **баг-репорт** (bug report, дефект-репорт).

## Структура баг-репорта

| Поле | Что писать | Пример |
|---|---|---|
| **Заголовок** | Что? Где? Когда? — в одной строке | «Корзина: повторное добавление товара заменяет количество вместо суммирования» |
| **Окружение** | Стенд, версия, браузер, ОС | QA Burger 1.0.0, localhost, Chrome 130, Windows 11 |
| **Предусловия** | Что нужно до шагов | Пользователь user вошёл, корзина пуста |
| **Шаги воспроизведения** | Пронумерованные, минимальные | 1. … 2. … 3. … |
| **Фактический результат** | Что произошло | В корзине 1 шт. |
| **Ожидаемый результат** | Что должно быть + ссылка на требование | 3 шт. (требование 11) |
| **Severity** | Серьёзность | Major |
| **Priority** | Срочность | High |
| **Вложения** | Скриншот, видео, лог, запрос/ответ (curl) | screenshot.png, curl-запрос |

### Пример хорошего баг-репорта

```text
Заголовок:   [Корзина] Повторное добавление товара заменяет количество вместо суммирования

Окружение:   QA Burger 1.0.0 (localhost:8081), баг воспроизводится и через UI, и через API

Предусловия: Пользователь user/user123 вошёл, корзина пуста

Шаги:
  1. POST /api/cart/items  {"productId": 1, "quantity": 2}
  2. POST /api/cart/items  {"productId": 1, "quantity": 1}

Фактический результат:  в ответе items[0].quantity = 1, total = 289.90
Ожидаемый результат:    items[0].quantity = 3, total = 869.70
                        (требование 11: «Повторное добавление суммирует количество»)

Severity: Major — неверная сумма заказа, клиент получает не то, что хотел
Priority: High  — затрагивает каждого покупателя

Вложения: curl-запросы, скриншот корзины
```

## Правила хорошего баг-репорта

1. **Один баг — один репорт.** Нашли три проблемы — заведите три репорта.
2. **Минимальные шаги.** Уберите всё лишнее, оставьте кратчайший путь к багу.
3. **Воспроизведите ещё раз** перед заведением. Если воспроизводится не всегда — укажите частоту («3 из 10 попыток»).
4. **Факт и ожидание — конкретно**, с числами, текстами ошибок, кодами ответов.
5. **Без эмоций и оценок**: не «всё сломано, ужас», а факты.
6. **Проверьте, нет ли уже такого бага** в трекере (дубликаты раздражают).
7. **Приложите доказательства**: для UI — скриншот/видео, для API — запрос и ответ (лучше в виде команды curl, модуль 8), для падений — лог/стектрейс.

> ❌ **Плохой заголовок:** «Не работает корзина». Что именно? Где? При каких условиях?

> ❌ **Плохие шаги:** «Добавить товары и посмотреть». Какие товары? Сколько? Куда смотреть?

## Severity и Priority — главный вопрос собеседований

**Severity (серьёзность)** — насколько баг **ломает систему**. Определяет QA.

| Уровень | Значение | Пример в QA Burger |
|---|---|---|
| **Blocker** | Работа невозможна, обходного пути нет | Приложение не запускается; нельзя оформить ни один заказ |
| **Critical** | Ключевая функция не работает или потеря данных/денег, безопасность | Видны чужие заказы (BUG-204); заказ считается оплаченным без оплаты (BUG-503) |
| **Major** | Важная функция работает неправильно, но есть обходной путь | Количество не суммируется (BUG-302) — можно указать сразу нужное |
| **Minor** | Незначительная ошибка, не мешающая основному сценарию | Счётчик корзины показывает число позиций, а не штук (BUG-701) |
| **Trivial** | Косметика | Опечатка в подсказке, съехала иконка |

**Priority (приоритет)** — насколько **срочно** чинить. Определяет менеджер/Product Owner с учётом бизнеса.

| Уровень | Значение |
|---|---|
| **High** | Чинить немедленно / в этом релизе |
| **Medium** | В ближайших спринтах |
| **Low** | Когда будет время |

### Они независимы!

| | Высокий приоритет | Низкий приоритет |
|---|---|---|
| **Высокая серьёзность** | Падает оплата → чинить срочно | Падение при экспорте в формат, которым пользуется 1 клиент раз в год |
| **Низкая серьёзность** | Опечатка в названии компании на главной странице | Съехала иконка в редком разделе настроек |

> 💡 Классический вопрос: «Приведите пример бага с низкой серьёзностью и высоким приоритетом». Ответ: опечатка в логотипе или названии бренда на главной странице — ничего не ломает, но позорит компанию перед всеми клиентами.

## Жизненный цикл бага

```text
 New ──▶ Open/Assigned ──▶ In Progress ──▶ Fixed/Resolved ──▶ Verification ──▶ Closed
  │                                                              │
  ├──▶ Rejected (не баг / дубликат / не воспроизводится)         └──▶ Reopened ──▶ (снова In Progress)
  └──▶ Deferred (отложен)
```

- **New** — QA завёл баг.
- **Open / Assigned** — баг подтвердили и назначили разработчику.
- **In Progress** — разработчик чинит.
- **Fixed / Resolved** — исправлен, ждёт проверки.
- **Verification** — QA проверяет исправление (**re-test**) и рядом (**регресс**).
- **Closed** — подтверждено, баг закрыт.
- **Reopened** — исправление не помогло, баг вернулся к разработчику.
- **Rejected** — не баг (так задумано), дубликат или не воспроизводится.
- **Deferred** — решили чинить позже.

## Где заводят баги

**Баг-трекеры:** Jira (самая распространённая), YouTrack, GitLab Issues, GitHub Issues, Redmine.

## Практика: Priority Poker

В разделе [Тренажёры](#/games) есть игра [**Priority Poker**](#/game/priority-poker): вам показывают описание бага, а вы выставляете severity и priority. Сыграйте пару раундов после этого урока.

```quiz
- q: Кто обычно определяет priority бага?
  options: [Тестировщик, Менеджер / Product Owner, Пользователь]
  answer: 1
- q: Пользователь видит чужие заказы с адресами. Какая severity?
  options: [Minor, Major, Critical]
  answer: 2
  explain: Это утечка персональных данных — проблема безопасности.
- q: Пример бага с низкой серьёзностью, но высоким приоритетом?
  options:
    - Опечатка в названии компании на главной странице
    - Падение сервера при оплате
    - Неверный расчёт налогов в годовом отчёте
  answer: 0
- q: Что из этого — хороший заголовок баг-репорта?
  options:
    - «Ничего не работает!!!»
    - «[Заказ] Промокод SALE10 даёт скидку 19% вместо 10%»
    - «Баг в заказе»
  answer: 1
- q: Исправленный баг снова воспроизводится. В какой статус его переводят?
  options: [Closed, Rejected, Reopened]
  answer: 2
- q: Нашли две разные проблемы на одной странице. Сколько баг-репортов завести?
  options: ["Один", "Два"]
  answer: 1
```

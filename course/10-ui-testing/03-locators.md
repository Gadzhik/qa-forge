**Локатор** — правило, по которому тест находит элемент на странице. Хороший локатор:
- находит **ровно нужный** элемент (не ноль и не десять);
- **устойчив** к изменениям вёрстки;
- **читается** человеком.

## CSS-селекторы

| Селектор | Что находит | Пример |
|---|---|---|
| `tag` | по тегу | `button` |
| `#id` | по id | `#username` |
| `.class` | по классу | `.btn-add` |
| `.a.b` | оба класса сразу | `.btn.btn-add` |
| `[attr]` | есть атрибут | `[disabled]` |
| `[attr=value]` | атрибут равен | `[data-testid=add-to-cart]` |
| `[attr^=v]` / `[attr$=v]` / `[attr*=v]` | начинается / заканчивается / содержит | `[href^='/product/']` |
| `tag[attr=v]` | тег + атрибут | `input[name=email]` |
| `A B` | B **где-угодно внутри** A | `[data-testid=product-card] button` |
| `A > B` | B — **прямой** ребёнок A | `form > button` |
| `A + B` | B сразу **после** A (сосед) | `label + input` |
| `A ~ B` | B где-то после A на том же уровне | `h1 ~ p` |
| `:nth-child(n)` | n-й ребёнок | `tr:nth-child(2)` |
| `:first-child` / `:last-child` | первый / последний | `li:last-child` |
| `:not(...)` | исключение | `button:not([disabled])` |
| `A, B` | A **или** B | `#q, #search-input` |

Примеры для QA Burger:

```css
[data-testid=product-card][data-product-id='1']     /* карточка товара с id 1 */
[data-testid=product-card] [data-testid=add-to-cart] /* кнопки «В корзину» внутри карточек */
#staff tbody tr:nth-child(2) td:last-child          /* зарплата во второй строке таблицы */
input[type=checkbox]:checked                         /* отмеченные чекбоксы */
```

> 💡 Значение атрибута можно писать без кавычек, если в нём нет пробелов и спецсимволов: `[data-testid=cart-count]`. С пробелами или цифрой в начале — в кавычках: `[data-product-id='1']`.

## XPath

**XPath** — язык путей в XML/HTML-дереве. Мощнее CSS: умеет искать **по тексту** и ходить **вверх** по дереву.

| XPath | Что находит |
|---|---|
| `//button` | все `button` где угодно (`//` — на любом уровне) |
| `/html/body/div` | абсолютный путь от корня (так **не делают** — ломается от любого изменения) |
| `//input[@id='username']` | по атрибуту (`@` — атрибут) |
| `//*[@data-testid='cart-count']` | любой тег (`*`) с атрибутом |
| `//button[text()='Войти']` | по **точному** тексту |
| `//a[contains(text(), 'бургер')]` | текст **содержит** |
| `//*[contains(@class, 'btn-add')]` | атрибут содержит |
| `//h1[normalize-space()='Меню']` | текст без лишних пробелов |
| `//div[@data-testid='product-card'][2]` | второй такой элемент (нумерация с **1**!) |
| `//a[text()='Кола 0.5']/ancestor::div[@data-testid='product-card']` | подняться к **предку** |
| `//td[text()='Вера']/following-sibling::td[2]` | соседняя ячейка справа |
| `//label[text()='Email']/following-sibling::input` | поле после подписи |
| `(//button)[last()]` | последняя кнопка на странице |
| `//button[@type='submit' and not(@disabled)]` | логика `and`, `or`, `not()` |

**Главная сила XPath** — найти элемент **по связи с текстом**: «кнопка "В корзину" в карточке товара "Кола 0.5"»:

```text
//a[text()='Кола 0.5']/ancestor::*[@data-testid='product-card']//button
```

CSS так не умеет (у него нет поиска по тексту и движения вверх).

## CSS или XPath?

| | CSS | XPath |
|---|---|---|
| Читаемость | Короче, проще | Длиннее |
| Поиск по тексту | ❌ | ✅ |
| Движение вверх (к родителю) | ❌ (`:has()` в новых браузерах — частично) | ✅ |
| Скорость | Чуть быстрее | Чуть медленнее (неважно на практике) |

Правило: **по умолчанию CSS** (`data-testid`, `id`), **XPath** — когда нужен текст или навигация по дереву.

## Устойчивость локаторов — главное

Сравните локаторы одной кнопки «В корзину» у первого товара:

| Локатор | Оценка |
|---|---|
| `/html/body/main/div[2]/div[1]/form/button` | ❌ сломается от любой новой обёртки |
| `.grid > div:nth-child(1) > form > button` | ❌ зависит от вёрстки и порядка |
| `.btn-add` | ⚠️ класс для стилей; в дизайне v2 его уже нет |
| `#add-1` | ⚠️ ок, пока id не переименуют (в v2 id нет) |
| `//button[text()='В корзину']` | ⚠️ сломается при смене текста или перевода сайта |
| `[data-testid=product-card][data-product-id='1'] [data-testid=add-to-cart]` | ✅ специальные метки, не зависят от вёрстки |

**Порядок предпочтений:** `data-testid` → `id` → `name` / `aria-*` / `role` → осмысленный текст → классы → структура. Структурные пути (`div > div > div`) и индексы — в последнюю очередь.

> 🧪 **Попробуй сам.** Откройте каталог QA Burger. В DevTools → Elements → Ctrl+F проверьте локаторы из таблицы. Потом переключите дизайн на v2 (ссылка внизу) и проверьте снова: какие ещё работают?

## Проверка локатора

1. **DevTools → Elements → Ctrl+F** (⌘F) — вводите CSS или XPath, видите количество совпадений (`1 of 1`).
2. **Console**: `document.querySelectorAll("CSS")` или `$x("XPATH")`.
3. Расширения браузера: SelectorsHub, ChroPath.

## Как выглядит HTTP-запрос

HTTP — текстовый протокол. Запрос на добавление в корзину на самом деле выглядит так:

```http
POST /api/cart/items HTTP/1.1
Host: localhost:8081
Content-Type: application/json
Accept: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIyIn0.abc123

{"productId": 1, "quantity": 2}
```

1. **Стартовая строка**: **метод** (`POST`), **путь** (`/api/cart/items`), версия протокола.
2. **Заголовки** (headers): строки `Имя: значение` — служебная информация о запросе.
3. **Пустая строка** — граница.
4. **Тело** (body) — данные. Есть не у всех запросов (у `GET` обычно нет).

## Как выглядит ответ

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 158
Date: Mon, 12 May 2024 12:01:15 GMT

{"items":[{"productId":1,"name":"Классический бургер","price":289.90,"quantity":2,"lineTotal":579.80}],"totalQuantity":2,"total":579.80}
```

1. **Строка статуса**: версия, **код** (`200`) и его текстовое описание (`OK`).
2. **Заголовки ответа**.
3. Пустая строка.
4. **Тело** ответа.

## Методы

Метод говорит, **что сделать** с ресурсом:

| Метод | Смысл | Тело запроса | Пример в QA Burger |
|---|---|---|---|
| **GET** | Получить | Нет | `GET /api/products/1` |
| **POST** | Создать / выполнить действие | Да | `POST /api/orders`, `POST /api/orders/1/pay` |
| **PUT** | Заменить целиком | Да | `PUT /api/products/1` (админ) |
| **PATCH** | Изменить частично | Да | (нет в QA Burger) |
| **DELETE** | Удалить | Обычно нет | `DELETE /api/cart/items/1` |
| **HEAD** | Как GET, но только заголовки | Нет | — |
| **OPTIONS** | Какие методы разрешены (используют браузеры для CORS) | Нет | — |

### Безопасность и идемпотентность — частый вопрос собеседований

- **Безопасный** метод не меняет данные на сервере: `GET`, `HEAD`, `OPTIONS`.
- **Идемпотентный** метод даёт одинаковый результат при повторах: сделать 1 раз или 10 — состояние сервера одинаковое. Идемпотентны `GET`, `PUT`, `DELETE`. **`POST` — нет**: два `POST /api/orders` создадут два заказа.

Для тестировщика это источник проверок: что будет при повторной отправке? Двойной клик по «Оплатить» — это повторный `POST /pay` (BUG-502).

## Коды ответа

Код — первое, что проверяет любой API-тест. Первая цифра — класс:

| Класс | Значение |
|---|---|
| **1xx** | Информационные (редко встречаются) |
| **2xx** | ✅ Успех |
| **3xx** | ↪ Перенаправление |
| **4xx** | ❌ Ошибка **клиента**: неверный запрос |
| **5xx** | 💥 Ошибка **сервера**: сервер сломался |

Самые важные коды:

| Код | Название | Когда | В QA Burger |
|---|---|---|---|
| **200** | OK | Успех | `GET /api/products` |
| **201** | Created | Ресурс создан | `POST /api/orders`, регистрация |
| **204** | No Content | Успех, тела нет | `DELETE /api/cart`, `POST /api/admin/reset` |
| **301 / 302** | Moved / Found | Перенаправление на другой адрес (заголовок `Location`) | страница `/cart` без входа → `/login` |
| **304** | Not Modified | Ресурс не изменился, берите из кэша | — |
| **400** | Bad Request | Некорректный запрос: не тот формат, не прошла валидация | количество 0, пароль «123» |
| **401** | Unauthorized | **Не аутентифицирован**: нет токена или он неверный | `/api/cart` без токена |
| **403** | Forbidden | Аутентифицирован, но **нет прав** | `POST /api/products` под обычным пользователем |
| **404** | Not Found | Ресурса нет | `/api/products/999` |
| **405** | Method Not Allowed | Метод не поддерживается | `DELETE /api/products` |
| **409** | Conflict | Конфликт с текущим состоянием | повторная оплата, занятый email |
| **415** | Unsupported Media Type | Не тот `Content-Type` | POST JSON без заголовка |
| **422** | Unprocessable Entity | Данные корректны по форме, но не по смыслу | (вариант 400 в некоторых API) |
| **429** | Too Many Requests | Превышен лимит запросов | — |
| **500** | Internal Server Error | Сервер упал с ошибкой | BUG-104 |
| **502 / 503 / 504** | Bad Gateway / Service Unavailable / Gateway Timeout | Проблемы прокси, сервис недоступен, таймаут | стенд перезапускается |

> 💡 **500 — это всегда баг.** Сервер никогда не должен отвечать 500 на любой, даже самый кривой запрос клиента — он должен вернуть понятную 4xx-ошибку. Если негативный тест получил 500 — заводите баг.

> 💡 **401 vs 403** — любимый вопрос собеседований. 401: «я не знаю, кто вы» (войдите). 403: «я знаю, кто вы, но вам нельзя».

## Заголовки

| Заголовок | Где | Значение |
|---|---|---|
| `Content-Type` | запрос и ответ | Формат тела: `application/json`, `text/html`, `multipart/form-data`, `application/xml` |
| `Accept` | запрос | Какой формат ответа клиент хочет получить |
| `Authorization` | запрос | Данные для входа: `Bearer <токен>` или `Basic <base64>` |
| `Cookie` / `Set-Cookie` | запрос / ответ | Cookies (урок 8.5) |
| `Location` | ответ | Куда перенаправить (3xx) или где созданный ресурс (201) |
| `Content-Length` | оба | Размер тела в байтах |
| `User-Agent` | запрос | Кто клиент (браузер, curl, Java) |
| `Cache-Control` | ответ | Правила кэширования |
| `X-Request-Id` / `traceparent` | оба | Идентификатор запроса для поиска в логах (модуль 16) |

> ⚠️ Отправили JSON, но забыли `Content-Type: application/json` — многие серверы ответят **415** или 400. Классическая ошибка в первых API-тестах.

## Тело и форматы

- **JSON** — основной формат API (урок 6.6).
- **XML** — SOAP-сервисы и старые системы.
- **form-data / x-www-form-urlencoded** — отправка HTML-форм; `multipart/form-data` — загрузка файлов.
- **Бинарные данные** — скачивание PDF, картинок (`Content-Type: application/pdf`).

## Зачем нужен Git

Представьте, что вы пишете автотесты, и всё работало, а после вчерашних правок сломалось. Что именно вы поменяли? Как вернуть рабочую версию? А если над тестами работают пять человек одновременно — как не затереть изменения друг друга?

**Git** — **система контроля версий**. Она:
- хранит **всю историю** изменений проекта: кто, когда, что и зачем поменял;
- позволяет **вернуться** к любой прошлой версии;
- позволяет работать **параллельно** в разных «ветках» и потом объединять работу;
- позволяет **обмениваться** кодом через сервер (GitHub, GitLab).

Весь код в IT-компаниях хранится в Git. Автотесты — тоже код, поэтому Git нужен каждый день.

## Основные понятия

| Понятие | Что это |
|---|---|
| **Репозиторий (repo)** | Папка проекта, за которой следит Git. Вся история хранится в скрытой подпапке `.git` |
| **Коммит (commit)** | «Снимок» состояния файлов с описанием. Как сохранение в игре |
| **Рабочая копия** | Файлы, которые вы видите и редактируете |
| **Индекс (staging area)** | «Зона подготовки»: изменения, которые войдут в следующий коммит |
| **Ветка (branch)** | Независимая линия истории (урок 2.2) |
| **Удалённый репозиторий (remote)** | Копия на сервере (GitHub, GitLab) (урок 2.3) |

Жизнь изменения в Git:

```text
  Рабочая копия  ──git add──▶  Индекс  ──git commit──▶  История (.git)
  (изменили файл)              (подготовили)           (сохранили снимок)
```

**Почему два шага (add, потом commit)?** Чтобы собрать в один коммит только то, что относится к одной задаче. Например, вы поправили тест корзины и случайно — настройки. В коммит «Исправлен тест корзины» добавите только файл теста.

## Первоначальная настройка

Один раз после установки скажите Git, кто вы — это имя будет в каждом коммите:

```bash
git config --global user.name "Анна Иванова"
git config --global user.email "anna@example.com"
```

- `git config` — изменить настройки Git;
- `--global` — для всех репозиториев на этом компьютере (настройки сохраняются в файле `~/.gitconfig`);
- `user.name` / `user.email` — имя и почта автора коммитов. Почту лучше указать ту же, что на GitHub.

Ещё две полезные настройки:

```bash
git config --global init.defaultBranch main
git config --global core.autocrlf input
```

- `init.defaultBranch main` — главная ветка новых репозиториев будет называться `main` (современный стандарт; раньше было `master`);
- `core.autocrlf` — как обращаться с концами строк. В Windows строки в файлах заканчиваются символами CRLF, в macOS/Linux — LF. Чтобы в репозитории не было мешанины, в **Windows** ставят `true` (в репозиторий LF, на диск CRLF), в **macOS/Linux** — `input` (при коммите CRLF превращается в LF).

```tabs
Windows: |
  ~~~powershell
  git config --global core.autocrlf true
  ~~~
macOS / Linux: |
  ~~~bash
  git config --global core.autocrlf input
  ~~~
```

> 💡 В нашем курсе есть файл `.gitattributes` — он задаёт концы строк для конкретных типов файлов (например, `*.sh` всегда LF, иначе bash-скрипты сломаются). Это надёжнее глобальной настройки, потому что работает у всех, кто клонирует проект.

## Практика: свой первый репозиторий

Создадим учебный репозиторий для заметок по курсу.

```bash
mkdir qa-notes
cd qa-notes
git init
```

- `mkdir qa-notes` — создать папку;
- `cd qa-notes` — войти в неё;
- `git init` — превратить папку в репозиторий: Git создаёт скрытую папку `.git`. Ответ: `Initialized empty Git repository in .../qa-notes/.git/`.

Создайте файл `README.md` с любым текстом (в IDEA, Блокноте или командой):

```bash
echo "# Мои заметки по QA" > README.md
```

`echo` печатает текст, а `>` записывает его в файл.

### git status — что происходит?

```bash
git status
```

Самая частая команда. Показывает состояние:

```text
On branch main
No commits yet
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        README.md
```

- `Untracked files` — **неотслеживаемые**: Git видит файл, но пока не следит за ним.

> 💡 Не знаете, что делать дальше? Выполните `git status` — Git сам подсказывает следующие команды (строки в скобках).

### git add — подготовить

```bash
git add README.md
```

Добавить файл в индекс. Варианты:
- `git add .` — **все** изменённые и новые файлы в текущей папке и ниже (точка = «текущая папка»);
- `git add src/` — все файлы в папке `src`.

Снова `git status` — файл теперь в разделе `Changes to be committed` (готов к коммиту).

### git commit — сохранить снимок

```bash
git commit -m "Добавлен README"
```

- `commit` — создать коммит из того, что лежит в индексе;
- `-m "..."` (*message*) — описание коммита.

> ⚠️ Если забыть `-m`, Git откроет текстовый редактор для ввода сообщения (часто это **vim**, и новички в нём «застревают»). Выход из vim без сохранения: нажмите `Esc`, наберите `:q!` и Enter. Чтобы такого не было, всегда пишите `-m`.

**Как писать сообщения коммитов:** кратко, по делу, что сделано: «Добавлен тест на пустую корзину», «Исправлен локатор кнопки оплаты». Плохо: «fix», «правки», «asdf».

### git log — история

```bash
git log --oneline
```

- `log` — показать историю коммитов (новые сверху);
- `--oneline` — по одной строке на коммит: короткий хеш и сообщение.

```text
a1b2c3d (HEAD -> main) Добавлен README
```

`a1b2c3d` — **хеш** коммита, его уникальный идентификатор. `HEAD` — указатель «где я сейчас».

### git diff — что изменилось

Измените `README.md` (допишите строчку). Затем:

```bash
git diff
```

Покажет построчно, что изменилось относительно последнего коммита: строки с `+` добавлены, с `-` удалены. `git diff --staged` — изменения, уже добавленные в индекс.

### Отмена изменений

```bash
git restore README.md            # вернуть файл к состоянию последнего коммита (правки пропадут!)
git restore --staged README.md   # убрать файл из индекса, но оставить правки в файле
```

> ⚠️ `git restore файл` безвозвратно стирает несохранённые в коммите правки этого файла. Будьте внимательны.

## .gitignore — что не хранить в Git

Не всё нужно коммитить: результаты сборки (`target/`), настройки IDE (`.idea/`), логи, отчёты, пароли. Их перечисляют в файле `.gitignore` в корне репозитория:

```text
# Результаты сборки Maven
target/
# Настройки IntelliJ IDEA
.idea/
*.iml
# Отчёты и логи
allure-results/
*.log
```

- строка с `#` — комментарий;
- `target/` — игнорировать папку `target` где угодно в проекте;
- `*.log` — все файлы с расширением `.log` (`*` — «что угодно»).

Посмотрите файл `.gitignore` в корне нашего курса — он устроен так же.

> ❌ **Никогда не коммитьте пароли, токены и ключи.** История Git хранится вечно: даже если удалить файл следующим коммитом, пароль останется в прошлом коммите. Для секретов используют переменные окружения (модуль 6).

## Git в IntelliJ IDEA

Всё то же самое можно делать мышкой:
- **Commit** (Ctrl+K / ⌘K) — окно коммита: галочками выбираете файлы (это и есть `git add`), пишете сообщение, жмёте *Commit*;
- **Git → Show History** / вкладка **Git** внизу (Alt+9 / ⌘9) — история и ветки;
- изменённые строки подсвечиваются полоской слева от кода; клик по ней — откатить изменение.

> 💡 Понимать команды терминала всё равно нужно: в CI (модуль 15) и на собеседованиях никакой мышки нет.

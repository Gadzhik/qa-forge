DevTools (F12, ⌥⌘I на macOS) — набор инструментов, встроенный в Chrome, Firefox, Edge и Safari. Тестировщик пользуется ими каждый день: смотрит запросы к серверу, ищет элементы для автотестов, читает ошибки JavaScript, проверяет cookies.

## Elements — структура страницы

Показывает **HTML-код** страницы в виде дерева (DOM, разберём в модуле 10).

- **Выбрать элемент на странице:** кнопка со стрелкой в левом верхнем углу DevTools (Ctrl+Shift+C / ⌘⇧C), затем клик по элементу — DevTools подсветит его код.
- Двойной клик по тексту или атрибуту — **редактировать** прямо на странице (только у вас, до перезагрузки). Полезно, чтобы проверить, как вёрстка выдержит длинный текст.
- **Поиск по DOM:** в Elements нажмите Ctrl+F (⌘F) и введите CSS-селектор или XPath — DevTools покажет, сколько элементов подходит (`1 of 20`). Это главный способ проверять **локаторы** для UI-тестов.

> 🧪 **Попробуй сам.** Откройте каталог QA Burger, в Elements нажмите Ctrl+F и введите `[data-testid=product-card]`. Сколько найдено? Теперь `[data-testid=add-to-cart]`. Переключите дизайн на v2 (ссылка внизу страницы) и повторите — число то же, хотя вёрстка другая. Об этом — модуль 10.

## Console — консоль JavaScript

- **Красные ошибки** — сбои JavaScript на странице. Часто это баг: что-то не работает, а пользователь видит лишь «ничего не произошло».
- Здесь можно **выполнять JavaScript**. Например:

```javascript
document.querySelectorAll('[data-testid=product-card]').length
```

- `document` — вся страница;
- `querySelectorAll('...')` — найти все элементы по CSS-селектору;
- `.length` — их количество.

```javascript
document.cookie
```

Показать cookies страницы (кроме защищённых флагом HttpOnly).

## Network — запросы к серверу

Самая важная вкладка для тестировщика API и веба.

1. Откройте DevTools **до** действия (запросы, сделанные до открытия, не показываются — тогда обновите страницу).
2. Фильтры: **All**, **Fetch/XHR** (запросы JavaScript к API), **Doc** (сами страницы), **JS**, **CSS**, **Img**.
3. Галочка **Preserve log** — не очищать список при переходе на другую страницу (нужно, когда форма отправляется и страница перезагружается).
4. Галочка **Disable cache** — не брать файлы из кэша браузера.

Клик по запросу:

| Вкладка | Что там |
|---|---|
| **Headers** | URL, метод (GET/POST...), **статус** ответа (200, 404, 500...), заголовки запроса и ответа |
| **Payload** | Что отправили: тело запроса, параметры |
| **Preview / Response** | Что ответил сервер (JSON удобно смотреть в Preview) |
| **Timing** | Сколько длился запрос и почему |
| **Cookies** | Какие cookies ушли и пришли |

### Copy as cURL

Правый клик по запросу → **Copy → Copy as cURL**. В буфере окажется готовая команда, повторяющая этот запрос из терминала. Её прикладывают к баг-репортам: разработчик выполнит её и сразу увидит проблему. С командой `curl` мы подробно познакомимся в модуле 8.

> 💡 В Windows выбирайте **Copy as cURL (bash)**, если будете выполнять в Git Bash, или **(cmd)** для командной строки. В PowerShell `curl` — это другая команда (псевдоним `Invoke-WebRequest`), поэтому пишите `curl.exe`.

### Эмуляция медленной сети

Выпадающее меню **No throttling** → **Slow 3G**. Страница начнёт грузиться медленно — так находят баги, когда пользователь успевает нажать кнопку дважды или видит «прыгающую» вёрстку. Не забудьте вернуть обратно!

## Application — хранилища браузера

- **Cookies** — небольшие данные, которые сайт хранит в браузере и отправляет с каждым запросом. В QA Burger после входа появляется cookie `token` с JWT — по нему сервер понимает, кто вы. Удалите её — и вы «вышли».
- **Local Storage / Session Storage** — хранилища данных для JavaScript.

> 🧪 **Попробуй сам.** Войдите в QA Burger. В **Application → Cookies → http://localhost:8081** найдите `token`. Скопируйте значение и вставьте на сайте https://jwt.io — увидите, что внутри: id пользователя, имя, роль, срок действия. В модуле 10 мы будем подкладывать такую cookie в браузер из автотеста, чтобы «войти» без формы логина.

## Device Toolbar — мобильная вёрстка

Кнопка с телефоном и планшетом (Ctrl+Shift+M / ⌘⇧M) — эмуляция экрана телефона. Выберите iPhone или Pixel и посмотрите на QA Burger: меню прячется под кнопку ☰. Проверять адаптивную вёрстку — тоже задача QA, а в модуле 10 мы автоматизируем это.

## Lighthouse

Вкладка **Lighthouse** — автоматический аудит страницы: скорость, доступность, SEO, лучшие практики. Полезно для быстрой оценки нефункциональных характеристик.

## Две категории типов

В Java все типы делятся на две группы, и разница между ними объясняет кучу «странностей».

**Примитивные** (`int`, `double`, `boolean`, `char`...) — переменная хранит **само значение**.

```java
int a = 5;
int b = a;   // в b скопировалось число 5
b = 10;      // a по-прежнему 5
```

**Ссылочные** (`String`, массивы, любые классы) — переменная хранит **ссылку** (адрес) на объект, который лежит в отдельной области памяти — **куче** (heap).

```java
int[] a = {1, 2, 3};
int[] b = a;     // скопировалась ССЫЛКА — теперь a и b указывают на один массив
b[0] = 99;
System.out.println(a[0]);   // 99 !
```

Картинка:

```text
  Переменные                 Куча (объекты)
  ┌────────┐
  │ a ─────┼──────┐
  └────────┘      ▼
  ┌────────┐   ┌──────────────┐
  │ b ─────┼──▶│ [99, 2, 3]   │
  └────────┘   └──────────────┘
```

Две переменные — один объект. Меняем через `b` — видим через `a`.

> 💡 Это частый источник багов в тестах: два теста получают «одну и ту же» коллекцию тестовых данных, один её меняет — второй неожиданно падает. Отсюда правило: тесты должны быть независимы и создавать свои данные.

## Сравнение: == и equals

- Для примитивов `==` сравнивает **значения**: `5 == 5` → `true`.
- Для ссылок `==` сравнивает **адреса**: «это один и тот же объект?».

```java
String s1 = new String("QA");
String s2 = new String("QA");
System.out.println(s1 == s2);        // false — два разных объекта
System.out.println(s1.equals(s2));   // true  — одинаковое содержимое
```

**Правило: строки (и любые объекты) сравниваем через `.equals(...)`, а не `==`.**

> ⚠️ Иногда `"QA" == "QA"` даёт `true` — Java переиспользует одинаковые строковые литералы (строковый пул). Из-за этого ошибка с `==` «то работает, то нет». Не полагайтесь на это: всегда `equals`.

## null

`null` — специальное значение ссылочной переменной: «ни на что не указывает».

```java
String name = null;
System.out.println(name.length());   // 💥 NullPointerException
```

Вызов метода у `null` — ошибка времени выполнения **NullPointerException** (NPE). Это, пожалуй, самая частая ошибка в Java-программах и в автотестах (например, тест извлёк из ответа поле, которого нет, и получил `null`).

Защита — проверка перед использованием:

```java
int length = (name == null) ? 0 : name.length();
```

(Это **тернарный оператор** `условие ? если_да : если_нет` — разберём в уроке 3.6.)

Примитивы не могут быть `null`: `int x = null;` — ошибка компиляции.

## Классы-обёртки

У каждого примитива есть «объектный двойник»:

| Примитив | Обёртка |
|---|---|
| `int` | `Integer` |
| `long` | `Long` |
| `double` | `Double` |
| `boolean` | `Boolean` |
| `char` | `Character` |

Зачем: коллекции (модуль 5) умеют хранить только объекты, а ещё обёртка может быть `null` («значения нет»). Java автоматически превращает одно в другое — это **автоупаковка** (autoboxing) и **распаковка**:

```java
Integer boxed = 5;      // int → Integer автоматически
int plain = boxed;      // Integer → int автоматически
Integer missing = null;
int oops = missing;     // 💥 NullPointerException при распаковке null
```

> ⚠️ Обёртки, как и любые объекты, сравнивают через `equals`. `Integer a = 1000, b = 1000; a == b` → `false`!

У обёрток есть полезные статические методы:

```java
int n = Integer.parseInt("42");          // строка → число
double d = Double.parseDouble("289.90"); // строка → дробное
String s = String.valueOf(42);            // число → строка
int max = Integer.MAX_VALUE;              // константы
```

`Integer.parseInt("сорок два")` бросит `NumberFormatException` — строка не похожа на число.

## Приведение типов

**Расширение** (из «меньшего» типа в «больший») — автоматически и безопасно:

```java
int i = 10;
long l = i;       // ✅
double d = i;     // ✅ 10.0
```

**Сужение** — только явно, с риском потерь:

```java
double price = 289.99;
int rubles = (int) price;   // 289 — дробная часть ОТБРОШЕНА (не округлена!)
```

`(int)` перед значением — **оператор приведения**: «я понимаю, что могу потерять данные, сделай».

## Целочисленное деление — ловушка №1

```java
int a = 3, b = 4;
double avg = (a + b) / 2;     // 3.0 — а не 3.5!
```

Почему: `(a + b)` и `2` — оба `int`, поэтому деление **целочисленное** (дробная часть отбрасывается): `7 / 2 = 3`. Только потом `3` превращается в `3.0`.

Исправления:

```java
double avg1 = (a + b) / 2.0;          // 2.0 — double, деление дробное → 3.5
double avg2 = (double) (a + b) / 2;   // привели к double до деления → 3.5
```

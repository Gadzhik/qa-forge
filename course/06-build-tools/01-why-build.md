## Проблема

В уроке 3.1 мы компилировали программу руками: `javac Hello.java`, потом `java Hello`. Для одного файла — нормально. А реальный проект автотестов:

- сотни файлов в десятках пакетов;
- десятки **библиотек**: JUnit, AssertJ, REST Assured, Selenide, Jackson, Allure... Каждая — jar-файл, и у каждой свои зависимости (REST Assured тянет за собой ещё ~20 библиотек);
- разные **версии** библиотек должны быть совместимы;
- нужно запускать тесты, собирать отчёты, упаковывать результат;
- и всё это должно одинаково работать у вас, у коллеги и на сервере CI.

Делать это руками невозможно. Для этого есть **системы сборки**: в мире Java это **Maven** и **Gradle**.

## Что делает система сборки

1. **Управляет зависимостями.** Вы пишете «мне нужен JUnit версии 5.13.4» — сборщик сам скачивает его и всё, от чего он зависит.
2. **Компилирует** код и тесты.
3. **Запускает тесты** и формирует отчёты.
4. **Упаковывает** результат (jar).
5. Даёт **единые команды** для всех: `./mvnw test` работает одинаково на любой машине.

## Зависимости и координаты

Каждая библиотека в мире Java имеет **координаты** — три части:

```text
groupId     : artifactId  : version
io.rest-assured : rest-assured : 5.5.7
```

- **groupId** — организация или проект (обычно перевёрнутый домен): `io.rest-assured`, `org.junit.jupiter`, `com.codeborne`;
- **artifactId** — имя библиотеки: `rest-assured`, `junit-jupiter`, `selenide`;
- **version** — версия.

Где они хранятся? В **Maven Central** — огромном публичном хранилище библиотек: https://central.sonatype.com. Найти нужную библиотеку и её координаты удобно на https://mvnrepository.com — там же есть готовые строки для Maven и Gradle.

## Локальный кэш

Скачанные библиотеки сохраняются на вашем компьютере:
- Maven: `~/.m2/repository` (в Windows `C:\Users\Имя\.m2\repository`);
- Gradle: `~/.gradle/caches`.

Поэтому первая сборка курса долгая (качается всё), а следующие — быстрые. Если кэш «испортился» (редко, но бывает при обрыве сети), папку можно удалить — всё скачается заново.

## Транзитивные зависимости

Вы подключаете REST Assured, а он сам зависит от Groovy, Apache HttpClient, Hamcrest... Это **транзитивные** (переходные) зависимости — сборщик подтягивает их автоматически.

Проблема: две ваши библиотеки могут требовать **разные версии** одной и той же третьей. Сборщик выбирает одну (у Maven — «ближайшую» в дереве), и иногда это ломает что-то. В нашем курсе мы именно с этим столкнулись: Spring Boot и тестовые библиотеки хотели разные версии Jackson, и учебное приложение не запускалось из тестов. Лечится явным указанием версии (в `dependencyManagement` или через **BOM**).

Посмотреть дерево зависимостей:

```bash
./mvnw -f exercises/m06-build-tools/pom.xml dependency:tree
```

`dependency:tree` — команда плагина зависимостей: печатает, какая библиотека кого притащила.

## BOM — согласованный набор версий

**BOM** (Bill Of Materials, «спецификация») — специальный pom со списком **согласованных версий** набора библиотек. Подключаете BOM — и больше не указываете версии каждой библиотеки отдельно. Примеры: `junit-bom` (все модули JUnit одной версии), `allure-bom`, `jackson-bom`, `spring-boot-dependencies`. Загляните в `exercises/pom.xml` курса — там подключено несколько BOM.

## Wrapper — сборщик, который не нужно устанавливать

Файлы `mvnw` / `mvnw.cmd` (Maven Wrapper) и `gradlew` / `gradlew.bat` (Gradle Wrapper) — маленькие скрипты, которые **сами скачивают нужную версию** Maven или Gradle при первом запуске. Благодаря им:
- не нужно ничего устанавливать, кроме Java;
- у всех в команде и на CI **одна и та же версия** сборщика.

Версия записана в `.mvn/wrapper/maven-wrapper.properties` (или `gradle/wrapper/gradle-wrapper.properties`). Хорошая практика — всегда запускать через wrapper (`./mvnw`, `./gradlew`), а не через установленный глобально `mvn`/`gradle`.

## Maven или Gradle?

| | Maven | Gradle |
|---|---|---|
| Файл проекта | `pom.xml` (XML) | `build.gradle` (Groovy) или `build.gradle.kts` (Kotlin) |
| Стиль | Декларативный, строгая структура | Гибкий, это почти программа |
| Порог входа | Ниже | Выше |
| Скорость | Обычная | Быстрее (кэш, инкрементальность) |
| Где встречается | Очень много проектов автотестов, корпоративный сектор | Android, многие современные проекты |

Нужно уметь читать оба. В курсе основной — Maven (уроки 6.2–6.3), Gradle разбираем в уроке 6.4 на демо-проекте.

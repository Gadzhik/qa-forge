## Что такое юнит-тест

Автотест — это **программа, которая проверяет другую программу**. Тест вызывает код, получает результат и сравнивает его с ожидаемым. Совпало — тест зелёный, нет — красный, и мы видим, что именно не так.

Вспомните схему из урока 1.1: ожидание → действие → сравнение факта с ожиданием. В коде она называется **AAA**:

```java
@Test
void totalIsPriceTimesQuantity() {
    // Arrange (подготовка): создаём объект и данные
    Cart cart = new Cart();
    cart.add("Кола", "99.00", 3);

    // Act (действие): вызываем то, что проверяем
    BigDecimal total = cart.total();

    // Assert (проверка): сравниваем факт с ожиданием
    assertEquals(new BigDecimal("297.00"), total);
}
```

Тот же шаблон известен как **Given / When / Then** (урок 1.4). Комментарии `// Arrange` писать не обязательно, но пустые строки между тремя частями делают тест читаемым.

## JUnit 5

**JUnit** — главный фреймворк для запуска тестов в Java. Версия 5 (её ещё называют JUnit Jupiter) — современный стандарт. Он:
- находит методы с аннотацией `@Test`;
- запускает каждый **отдельно**, на **новом объекте** тест-класса;
- считает тест упавшим, если из него «вылетело» исключение (в том числе от неудачной проверки);
- собирает результаты для IDE, Maven и отчётов.

Подключение (уже сделано в `exercises/pom.xml` через `junit-bom`):

```xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <scope>test</scope>
</dependency>
```

## Анатомия тест-класса

```java
package ru.qacourse.m07.tasks;

import org.junit.jupiter.api.Test;
import ru.qacourse.m07.sut.Cart;

import static org.junit.jupiter.api.Assertions.*;

class CartTest {

    @Test
    void newCartIsEmpty() {
        Cart cart = new Cart();
        assertTrue(cart.isEmpty());
    }
}
```

- тест-класс лежит в `src/test/java` и по соглашению называется `ЧтоТестируемTest`;
- `import static org.junit.jupiter.api.Assertions.*;` — подключаем все методы-проверки JUnit, чтобы писать `assertTrue(...)` без имени класса;
- `@Test` — **аннотация**: «этот метод — тест»;
- метод теста `void`, без параметров (параметры бывают — урок 7.6), модификатор `public` не нужен;
- имя метода описывает, **что** проверяем: `newCartIsEmpty`, `zeroQuantityIsRejected`. Не `test1`!

## Проверки JUnit (Assertions)

| Метод | Что проверяет |
|---|---|
| `assertEquals(ожидание, факт)` | равны (через `equals`) |
| `assertNotEquals(a, b)` | не равны |
| `assertTrue(условие)` / `assertFalse(условие)` | условие истинно / ложно |
| `assertNull(x)` / `assertNotNull(x)` | `null` / не `null` |
| `assertThrows(Тип.class, () -> вызов)` | вызов бросает исключение этого типа |
| `assertAll(() -> ..., () -> ...)` | выполнить все проверки и сообщить обо всех провалах сразу |
| `fail("сообщение")` | принудительно провалить тест |

> ⚠️ **Порядок аргументов в assertEquals: сначала ОЖИДАНИЕ, потом ФАКТ.** Если перепутать, тест будет работать, но сообщение об ошибке будет врать: `expected: <289.90> but was: <297.00>` вместо наоборот. В AssertJ (урок 7.3) такой путаницы нет.

Последним аргументом можно передать **сообщение**, которое появится при падении: `assertEquals(3, cart.quantityOf("Бургер"), "количество после повторного добавления");`.

### Проверка исключений

```java
@Test
void zeroQuantityIsRejected() {
    Cart cart = new Cart();
    IllegalArgumentException e = assertThrows(IllegalArgumentException.class,
            () -> cart.add("Кола", "99.00", 0));
    assertEquals("Количество должно быть от 1 до 99", e.getMessage());
}
```

- первый аргумент — какое исключение ожидаем;
- второй — **лямбда** с вызовом (урок 5.4): JUnit выполнит её сам и поймает исключение;
- `assertThrows` возвращает пойманное исключение — можно проверить сообщение.

## Запуск

- **IDEA:** зелёный ▶ слева от метода (один тест) или от класса (все тесты класса). Внизу — дерево результатов.
- **Терминал:** `./mvnw -f exercises/m07-junit/pom.xml test -Dtest=CartTest`.

## Что значит «хороший тест»

1. **Проверяет одну вещь.** Упал `zeroQuantityIsRejected` — сразу понятно, что сломано.
2. **Независим.** Не рассчитывает на то, что другой тест выполнился раньше. JUnit не гарантирует порядок запуска тестов!
3. **Детерминирован.** Каждый запуск даёт один и тот же результат.
4. **Конкретные ожидания.** `assertEquals(new BigDecimal("297.00"), total)`, а не `assertTrue(total.signum() > 0)`.
5. **Падает, когда есть баг.** Тест, который никогда не падает, бесполезен.

## Как проверяются задания модуля

Пункт 5 — главный. Как проверить, что тест **ловит баги**? В тестируемых классах (`exercises/m07-junit/src/main/java/ru/qacourse/m07/sut`) заложены **мутанты** — специально испорченные версии логики, которые можно включать. Проверка задания:

1. Запускает ваши тесты на **правильном** коде — они должны пройти.
2. Включает по очереди каждого мутанта — хотя бы один ваш тест должен **упасть**.

Если мутант «выжил» (все тесты прошли с испорченным кодом) — ваши тесты не проверяют это требование. Этот приём — **мутационное тестирование** — реально используется для оценки качества тестов (инструмент PIT).

Требования к классам — в их комментариях (Javadoc). Читайте их, как читали бы требования аналитика.

```task

text: |
  В `CartTest` допишите тесты для класса `Cart` (требования — в его Javadoc):
  - итог для товара с количеством больше 1;
  - повторное добавление того же товара суммирует количество;
  - количество 0 отклоняется исключением.

  Проверка включит ошибки «итог не учитывает количество» и «повторное добавление заменяет количество» — ваши тесты должны их поймать.
hint: |
  - `cart.add("Кола", "99.00", 3); assertEquals(new BigDecimal("297.00"), cart.total());`
  - Добавьте один товар дважды и проверьте `cart.quantityOf(...)`.
  - `assertThrows(IllegalArgumentException.class, () -> cart.add("Кола", "99.00", 0));`
```
